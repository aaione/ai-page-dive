## Confirmed（11 条）

### C1 [medium] panel 帧接收端不校验来源——伪造 task-error 可错标终局/移锚拒收
- **证据**：App.tsx:760 `chrome.runtime.onMessage.addListener(listener)` 全文件零处 sender 校验；task-error 主分支守卫仅 :620 finished 台账与 :625 taskId 比对
- **路径**：runtime.sendMessage 是扩展内广播（SW sendToPanel 同通道 sw.ts:280-286）——被 XSS 的面板从广播流拿到 taskId+tabId 后伪造 {t:'task-error'} 直发，绕过 SW 通过三道守卫，把已送达流标 undelivered；真 task-done 迟到被 finished 拒收，定性被永久改写。前提需先有面板 XSS（react-markdown 转义 + urlTransform 拦 javascript:，无已知向量）——定性纵深缺口
- **修法**：listener 加 sender 门槛（sender.url 以自家 sw.js 结尾），或 SW→panel 改专用 Port

### C2 [medium] missedErrBubble 缺 cancelled——收件箱补发的取消终局 tips 误落「已分享」
- **证据**：App.tsx:1108-1125 返回体无 cancelled；实时分支 :675 有；tips 判据 :656 `stopped=!!messages.at(-1)?.cancelled`
- **场景**：面板收起时点停止 → 重开补发 → stopped/undelivered 双 false → tips「已分享」与同屏气泡「已取消」矛盾，sr-only 播报同漏
- **修法**：补 `cancelled: mt.code === 'cancelled'` + SummarizeView.test 收件箱 cancelled 用例

### C3 [medium] __host-disconnected 不带 undelivered——未送达场景 tips 谎报「已分享」
- **证据**：App.tsx:721-739 分支只设 error/isError；sw.ts:907 断连入箱 code:'host-disconnected'；不在 UNDELIVERED_CODES
- **场景**：断连发生在 task-start 后、正文分片未送达 host 的窗口（spawn/传输期 host 崩溃）——恰是「分享未成功」目标场景却落「已分享」；且该码不在 ERROR_LABEL，missedErrBubble 兜底渲染「未知错误（码 host-disconnected）」
- **修法**：分支按 s.pending（或收到首 chunk 前）补 undelivered:true；ERROR_LABEL 补文案

### C4 [medium→low] ext-restarted 归「已送达」族失实——pdRunningTask 写入早于正文分片
- **证据**：sw.ts:1163 setRunningTask 位于 :1173 分片 while 之前；ext-restarted 不在集合
- **场景**：扩展更新打断正文传输窗口时 CLI 从未收到正文，但 commit 自述与代码事实不符
- **修法**：expectedChars 未设置时折算的 ext-restarted 落 undelivered 语义

### C5 [medium] resolveContentTab 二级 target 单例跨窗错页
- **证据**：sw.ts:1005-1014 级 2 `target?.id` 无 windowId 约束；r69 注释自认单例覆盖风险
- **场景**：双窗 B 窗点过 action 后，A 窗锚 tab 关闭点总结 → 级 2 命中 B 窗 tab → 静默提取 B 窗页面，取消/归档连带错位
- **修法**：级 2 限定 target 与 anchor 同 windowId，跨窗不兜底走 no-tab 终态

### C6 [medium] UNDELIVERED_CODES 漏收 content-mismatch
- **证据**：App.tsx:1094-1097 注释称其「已送达不在集内」，但 sw.ts:1213 语义为「正文传输确认超时已取消」——spawn 前即取消，CLI 从未收到完整正文
- **修法**：加入集合并修正头注释论证

### C7 [medium→low] UNDELIVERED_CODES 与 host code 联合类型零编译期联动
- **证据**：App.tsx:1097 手写 Set<string>；protocol.ts:253 code 联合无约束关联——host 新增 pre-delivery 码时静默按已送达分类
- **修法**：Set<HostCode|SwCode> 类型联动 + protocol.ts 注释标注同步义务

### C8 [medium] task.ts child 'error' 终局分支不对称：不 flushDelta 也不 persist ⚠️ 全仓唯一数据丢失类
- **证据**：task.ts:326-339 只 reap+cleanupCwd+onError('spawn-fail')；对照 finish() :437/:446、timeout :275/:299、isError :377 均发尾巴+落盘
- **场景**：spawn 成功后运行期错误（EPIPE/信号）时攒批 ≤8KB/50ms 尾巴静默丢弃、无 interrupted 落盘——用户此轮对话凭空消失
- **修法**：补 this.flushDelta() + void this.persist('interrupted')（flush 在 onError 前）

### C9 [medium] UNDELIVERED_CODES 17 项成员归属零测试——盖戳端半条链裸奔

### C10 [medium] App.tsx 1142 行零直接测试，r71 主修复面大半裸奔

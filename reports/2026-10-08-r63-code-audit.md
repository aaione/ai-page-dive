### medium（4）

1. **裸 cancel（无 taskId）三处保留，可跨窗口误杀别窗在跑任务（本轮新发现）**。`SummarizeView.tsx:448` / `App.tsx:882` 发 `{t:'cancel'}` 无 taskId；`sw.ts:551-557` 核验仅对带 taskId 帧生效，裸帧直达 `cancelCurrent()` 无条件杀全局单例 currentTask；host 侧 `stdio.ts:104-105` 无 taskId 的 task-cancel 落到 `at(-1)` 收割最近任务。触发链：双窗口双面板（r9-backlog 认可形态），A 窗跑 deep 总结、B 窗历史页点「继续对话」且该 CLI 已卸载（agentOk=false 降级路径**自动**发裸 cancel）→ A 窗任务被连坐砍掉。与 r59 T1「绝不错杀别窗口新任务」的修复意图自相矛盾（sw.ts:552-555 注释自述同族风险，带 taskId 路径已修，裸帧路径是遗留缺口）。**修法：裸 cancel 全部带 taskId；SW 侧对无 taskId 的 cancel 帧一律拒收（与 r59 T1 对称）。**
2. **[r62 遗留] UI 层 ~4263 行零组件测试（连三轮未清）**。全仓无 `*.test.tsx`，SummarizeView/App/Settings/HistoryView/Onboarding 五组件零覆盖，`@testing-library` 设施不存在；sw.test.ts:2-3 头注释自认「注释链记录的恰恰是真机手测发现的已修 bug」——防线错位在 UI 层缺位。r62 后四个提交未补一个组件用例（8816db8 刚改过 SummarizeView 授权反馈，无测试护航）。**修法：最低限度给 SummarizeView 流式渲染 + Settings/授权开关补 jsdom 组件冒烟，分批偿还。**

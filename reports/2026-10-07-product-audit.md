# PageDive 产品质量终审报告（第三轮）

> 审计日期：2026-10-07 · 6 维度审计 → 对抗核实 → 终审
> 基准 HEAD `75b5325`（main，本地领先 origin/main 55 提交），版本 0.1.4
> 上两轮基线：`reports/2026-10-05-product-audit.md`（0.1.3）、`reports/2026-10-06-product-audit.md`（0.1.4/r59）
> 评审口径特别说明：发布链（push/publish/tag）用户知情未授权，本轮按「断口期间的产品完整性」评审，不按「没发布=失格」；但断口本身对新用户安装主线的 100% E404 命中要如实计分。

## 头条裁决

**有条件是。**

代码本体连续第三轮维持高质量兑现：r60 把上轮唯一产品文案 medium（codex 恒标「不支持追问」）真删干净并与 README/实现三方归一；seq 水位跨任务、PDF 正则锚定（11 例重放零误报）、孤儿帧守卫、nm 17 帧白名单（与协议联合类型 17/17 逐字核对零漏）全部实证落地；上轮 Top 5 廉价债五条全清偿（历史空态/语言 hint/「原始信息：」前缀/authHint 两档/多引擎「⚠️ 未实施」标记——最后这条拖了两轮的账也清了）。213 用例全绿、七点版本门禁全绿、六条硬红线实测全守。

但断口在**扩大而非收敛**，且 r60 的修复自带新的堵点：

1. **发布断口恶化**：未推提交 51 → 55，registry 仍停 0.1.2，origin/main 的 install.sh 仍钉从未 publish 的 @0.1.3——任何照 GitHub README 走的新用户第一步 npm i 必 E404，且线上失败指引（EACCES/nvm/网络三档）把人引向完全不对症的权限排障。r60 写好的 E404 排障提示只在本地，用户够不着。
2. **r60 自己制造了下一次 push 的确定性红灯**：删「死 prop」noFollowUpHint 只删了一半——调用侧传参与解构残留，`tsc --noEmit` 两处硬错误（TS2322/TS2339），CI 扩展类型门禁下次 push 必红。这意味着上轮唯一 high 的修复动作（push）现在被 r60 自己堵住：照红灯 publish 破坏「CI 绿才发版」设计，不 publish 断口继续扩大。
3. **authHint 修复不完整且方向反了**：上轮明确要求「把 429 从额度误归拆出来」，r60 加了限流档但排在额度档**之后**求值——429 最高频人读文本 "Rate limit reached" 仍命中额度档，被指引去「升级套餐或切换账号」，对瞬时限流是完全错误的出路；网络档漏 Connection error/ECONNRESET/timeout 等六条主流形态；snake_case `rate_limit` 仍未闭合。

**改判条件（全部可验收，合计约 35 分钟）**：

1. 删 `SummarizeView.tsx:689-693` 传参与 `:1032` 解构（5 分钟）——push 的前置条件，否则 CI 必红。
2. 完成发布链：`npm publish` → `git push origin main` → `git tag v0.1.4`（顺序不能反，~10 分钟）——消灭唯一 high + 两个 medium + 四条 E404 链 low 的绝大部分。
3. authHint 修复收口：限流档提到额度档之前、网络档正则补全、`rate[ _-]?limit`（~20 分钟）。

以上完成后可改判「是」。**不构成改判障碍的**：CWS 商店材料（连续第三轮定性为发布运营待办，未恶化）；SPA 零等待/孤儿帧看门狗感知（low 打磨项）。

## 确认问题清单（共 18 项存活：high 1 / medium 3 / low 14）

### high（1）

**1. 线上安装主线断裂：registry 停 0.1.2，origin/main install.sh 钉从未 publish 的 @0.1.3，README curl 主线对新用户 100% E404——r60 的 E404 排障提示只修在本地未推送**
- 三位核实者全部 isReal=true/high confidence 维持 high。且比上轮更糟：origin/main 的 ci.yml 连 check-published 门禁都没有（该脚本也在未推送提交内），线上连检测层都不存在。修复 ~10 分钟，顺序严格：先 `npm publish` → `git push` → `git tag v0.1.4`。

### medium（3）

**2. E404 排障修复未交付到用户实际拉取的信道**——本地 install.sh:47 补了 E404 档，但新用户 `curl .../main/install.sh` 拉到的是 origin 版：钉 @0.1.3 + 失败指引仅 EACCES/nvm/网络三档。随发布链一并交付，零额外成本。
**3. authHint 修复不完整且方向反了**——"Rate limit reached" 仍被额度档先捕获→「升级套餐或切换账号」错误指引（r60 自认的高频第二失败面）；网络档漏 Connection error/ECONNRESET/timeout/connection closed 六条主流文本；`rate ?limit` 不容下划线。~20 分钟。
**4. 0.1.4 仍是「本地发布」**——55 提交未推（51→55 恶化）、零 tag、r59+r60 全部修复零 CI 覆盖，CHANGELOG「已发布」宣称持续失实。

### low（14）

## Top 5 必修（按投入产出排序）

**1. 删 `SummarizeView.tsx:689-693` 传参与 `:1032` 解构中的 noFollowUpHint（~5 分钟）**
push 的前置条件。不修则发布链第一步 CI 必红；修法则与 commit 意图一致（彻底删）。顺手把 `tsc --noEmit` 挂进 extension build 或根 test 脚本，防同类再犯。

**2. 完成发布链：`npm publish` → `git push origin main` → `git tag v0.1.4`（~10 分钟，顺序不能反）**
消灭唯一 high（#1）+ 两个 medium（#2/#4）+ E404 链三条 low 的主体。这是连续第三轮出现在必修清单第一位的项目——代码侧一切就绪，差的始终是这 10 分钟。

**3. authHint 修复收口（~20 分钟）**
限流档提到额度档之前（或额度档排除 `rate` 前缀）；网络档改 `/connection (error|reset|closed)|ECONNRESET|ECONNREFUSED|ENOTFOUND|ETIMEDOUT|timeout|timed out|network|fetch failed/i`；`rate ?limit` 改 `rate[ _-]?limit`；顺手给 429/529 加词边界。

**4. E404 兜底文案三处（~15 分钟，发布后仍有窗口期价值）**
横幅/Onboarding FAQ/install.sh 各预埋一条「E404 = 该版本尚未发布到 npm，稍后重试或到 GitHub releases 确认」——每次发版窗口期都会重现数小时，值得一次修死。

**5. 廉价债一波清（合计 ~40 分钟）**
Settings.tsx:211 补「（原始信息：…）」前缀与 App.tsx 逐字对齐（5 分钟）；「模式/档」五处统一（10 分钟）；App.tsx:246 陈旧注释（1 分钟）；SummarizeView 死 prop 删除时一并处理（已含在 Top 1）。host 行数余量 1 的腾挪（0.5-1 天）必须挡在任何 host 新功能之前——这是「再破线删功能」纪律的最后一格缓冲。

## Findings

### [major] F1 — followAgent 跨会话不重置：新会话/历史恢复后的 CLI 标识显示错误

- 证据：`apps/extension/src/sidepanel/SummarizeView.tsx:95`（`followAgent` state）、`:171-175`（`newChat` 不重置它）、`:190`（下拉 `value={hasSession ? (followAgent ?? effectiveAgent) : effectiveAgent}`）、`:218`（气泡头部 `agentId={followAgent && m.streaming !== true ? followAgent : effectiveAgent}`）
- 触发路径：① 用 claude 完成一轮总结（追问响应回带 `followAgent='claude'`）→ 点「新对话」→ 下拉选 codex 发送首轮总结 → 实际跑 codex，但 SW 首轮响应不含 `agentId`（`sw.ts:199` 返回 `{ok, taskId}`，仅 followUp 分支带 agentId，`sw.ts:197`）→ `followAgent` 仍为 'claude' → done 后 `hasSession=true`，下拉与气泡头部都显示 **claude**，实际执行的是 codex。② 历史恢复路径同理：`App.tsx:252-267` resumeHistory 不触碰 SummarizeView 内部 state，恢复后完成任何一轮，头部显示的是上一会话遗留的 followAgent。
- 影响：违背「头部展示与真实执行一致」的既有设计意图（SummarizeView.tsx:94 注释自述该目标）；多 CLI 用户的信任问题。
- 建议修法：`newChat()` 内 `setFollowAgent(null)`；resumeHistory 后首轮响应到达前不展示 followAgent（或 App 把 resume 的 agent 透传给 SummarizeView 重置）。另建议首轮 summarize 响应也回带 agentId（sw.ts:199 处 `return { ...r, agentId }`），显示链彻底闭环。

### [major] F2 — Settings：工作流正文「正在读取…」窗口内点保存，会用空正文 shadow 掉真实模式

- 证据：`apps/extension/src/sidepanel/Settings.tsx:150-161`（`selectWorkflow` 置 `body: ''` 等 `workflow-file` 帧）、`:185-199`（`saveWorkflow` 无 body 就绪守卫）、`:342`（placeholder 文案「正在读取…」只是 placeholder，不阻止保存）
- 触发路径：设置 → 模式 → 点选一个模式 → 在 `workflow-file` 帧到达前（host 忙/大目录扫描慢时窗口可达秒级）修改描述（触发 dirty）→ 点「保存」→ host 落盘用户副本 `body=''` → 该模式被空正文用户副本 shadow，总结时静默失效（选了「深度研读」实际发空指令）。readTimeout 防的是「超时文案被持久化」（Settings.tsx:163-169 注释），但**空 body 本身没有被防**。
- 影响：静默数据破坏 + 总结质量劣化（违背 v1 最高优先级「深度总结质量」），且用户无任何异常感知。
- 建议修法：`editor.body === '' && editor.originalName && !readTimeout` 期间禁用保存按钮（或保存前二次确认「正文尚未加载完成」）；内置模式在 body 未加载时干脆只读。

### [major] F3 — SW 中途死亡（OOM/更新/崩溃）时面板永久锁死，无任何看门狗

- 证据：`apps/extension/src/sidepanel/SummarizeView.tsx:100`（`running = activeId!==null || pending`，唯一解锁途径是收到终局帧）；`App.tsx:104-199`（所有状态迁移均由消息帧驱动，无超时兜底）；SW 死亡 = NM port 随之断连 = host 进程被 Chrome 终止 = **不再有任何终局帧**（`nmport.ts:29-33` port 随 SW 消亡；`__host-disconnected` 也不会发——SW 本身没了）
- 触发路径：任务流式输出中（activeId 非空）→ Chrome 因内存压力/扩展更新回收 SW → 面板继续显示「思考中…」，输入框禁用、停止钮点了发出去没人收（新 SW `currentTask=null` 返回 undefined）。面板此时仍存活（side panel 不随 SW 关闭）→ **永久 running**。逃生口只有用户自己想到点「新对话」或重开面板。
- 影响：低概率高伤害——一旦发生，产品表现为「彻底死机」。host 侧 10 分钟超时（task.ts:20,224-237）救不了这条路径（host 已死）。
- 建议修法：panel 侧加停看门狗——N 秒（建议 90-120s）无任何任务帧且 running 时，置 stale 态：提示「连接已中断，点击重试/新对话」，解锁输入框。

### [minor] F4 — 「停止」在 reading（提取）窗口内点击后数秒无任何反馈

- 证据：`SummarizeView.tsx:166-168`（cancel 纯发消息，不改本地 state）；`sw.ts:240-247`（cancelCurrent 对 host 发 task-cancel 并清 currentTask）；`packages/host/src/stdio.ts:78-80`（`tasks.get(...)?.cancel()`——提取窗口内 host 从未见过该 taskId，**静默忽略，无回帧**）
- 触发路径：点「总结」→ 立即点「停止」（重页面提取需数秒）→ UI 无任何变化，仍显示「正在读取正文」；提取完成后 SW `sw.ts:425` 检测 currentTask 已易主返回 `{error:'cancelled'}` → 面板才显示「已取消」并解锁。
- 判定：自愈（非锁死，见「已排除」#1），但停止钮数秒无响应 + 提取本身并未真正中止，体感是「按钮坏了」。
- 建议修法：cancel 时若 SW 返回 ok，panel 立即本地置「正在停止…」弱化态；或 SW 在提取窗口收到 cancel 时直接给 panel 补发一帧合成 `task-error(cancelled)`。

### [minor] F5 — HistoryView：搜索态下删除/删除失败后，搜索静默重置为全量列表（stale closure）

- 证据：`apps/extension/src/sidepanel/HistoryView.tsx:21-32`（listener 注册在 `[]` effect 里，捕获首帧渲染的 `refresh`，其默认参数 `query` 恒为 `''`）、`:27`（`deleted`/`delete-fail` → `refresh()`）、`:34-36`（refresh 定义）
- 触发路径：历史 → 搜索 "github" → 删除一条（成功或失败）→ `refresh()` 用捕获的 `query=''` 重拉 → 列表变全量，但搜索框仍显示 "github"——搜索框内容与列表不符。
- 建议修法：query 入 ref（或 effect 依赖 query 重新注册 listener）；refresh 后保持过滤条件。

### [minor] F6 — session-lost 文案承诺「本次将开始全新总结」，实际什么都不会发生

- 证据：`App.tsx:220`（`'会话已失效（扩展服务重启）——本次将开始全新总结'`）；处理仅追加错误气泡（App.tsx:222-234），无任何重新发起动作；用户输入的问题气泡留在原处，需手动重发
- 触发路径：SW 被 30s 回收且 storage.session 恢复失败（罕见）后点发送。
- 建议修法：文案改为「请重新发送本次问题（将开始全新总结）」，或错误气泡下加「重发」按钮。

### [minor] F7 — 追问会话中 CLI 下拉可切换但实际不生效（假可供性）

- 证据：`SummarizeView.tsx:189-195`（ModelDropdown 在 hasSession 时**未禁用**，对比 WorkflowDropdown 有 `disabled={hasSession}` + title 提示，:288-296）；`sw.ts:192-198`（followUp 无条件用 `lastSession.agentId`，忽略 panel 传来的 agentId）
- 触发路径：会话中把下拉从 claude 切到 codex → 发追问 → 实际仍跑 claude → 响应回带 `agentId:'claude'` 把下拉翻回 claude。用户短暂以为切成功了。
- 建议修法：与模式下拉对齐——hasSession 时禁用 + title「追问沿用首轮 CLI」。

### [minor] F8 — host 中途断连：流式对话被整个替换为「还差一步（仅此一次…）」安装引导

- 证据：`App.tsx:189-190`（`__host-disconnected` → `setHostOk(false)`）+ `:285`（hostOk===false 直接 return `<Onboarding/>`，丢弃当前对话视图）；`Onboarding.tsx:67`（标题按**全新安装**口吻：「还差一步（仅此一次…）」）
- 触发路径：正常使用中 host 进程崩溃（NM 断连）→ 用户正在看的流式总结瞬间消失，取而代之的是「复制命令装组件」的安装页——对已装用户是错误框架（应解释为「本机组件异常退出」）。Onboarding 轮询探活会在 host 恢复可用后自动 reload（Onboarding.tsx:32），但 NM host 不会自动重启，需 panel-ready 触发 probe 时由 `nmport.connect()` 重连拉起——这条自愈链成立（probe → connectNative 重spawn），等待期间文案误导。
- 建议修法：区分「从未安装」与「运行中断连」（可用 nmError/是否曾有成功会话判断），后者显示「本机组件连接中断，正在尝试重连…」而非安装引导。

### [minor] F9 — HistoryView 在 host 未连接时显示「暂无历史」，与事实不符

- 证据：`HistoryView.tsx:167`（`!items.length → 暂无历史`），无 host 可用性判断；对比 Settings 有「尚未获取到模式列表（本机 host 未连接？）」（Settings.tsx:301）

### [minor] F10 — 已装 host 但一个 CLI 都没有时，空状态指引缺失

- 证据：`SummarizeView.tsx:193`（下拉 fallback 仅「无可用 CLI」四个字）、`:608`（Placeholder 无条件渲染，无「需要 claude/codex」提示）；此时发送钮禁用（:546）、输入框可打字但 Enter 无效（:536）

### [minor] F11 — Settings 切换工作流/关闭面板时丢失未保存编辑，无确认

### [?] F12 — SW 合成 reading 占位帧与 summarize sendResponse 的到达顺序依赖隐式 FIFO

- 证据：`sw.ts:400`（占位帧 `chrome.runtime.sendMessage` 先发）与 `sw.ts:414-425`（错误经 sendResponse 后回）走不同回传通道；`App.tsx:119-131` task-status 的守卫是 `taskId!==null && !==m.taskId 才拒绝`——若 sendResponse（含 onStartResult 的 taskId:null 清场）先到、占位帧后到，占位帧会在 null 态下被**绑定**，产生一个永无终局的 streaming 气泡（running 锁死）

## 已排除（查证后非 bug）

1. **「reading 窗口点停止会永久锁死」——排除。** 表面看 host 对未知 taskId 的 task-cancel 静默忽略（stdio.ts:78-80）且无终局帧回；但 SW 提取完成后在 sw.ts:425 检测 `currentTask` 易主，经原 sendMessage 通道返回 `{error:'cancelled'}`，panel onStartResult 正常清场解锁（App.tsx:211-234）。实际表现是数秒延迟（见 F4），非锁死。
2. **「send() 中 beginTurn 调两次会清掉用户消息」——排除。** beginTurn 是追加语义（App.tsx:240-246 `messages:[...s.messages, 新消息]`），附件跳过提示与用户消息并存。
3. **「content-mismatch 取消后面板不收尾」——排除。** SW 合成的 task-error 帧带 taskId（sw.ts:286-288），此时 panel 绑定同 taskId，走正常终局分支。
4. **「取消追问轮后 hasSession 误判导致断链」——排除。** canFollowUp 要求 `!m.error`（SummarizeView.tsx:101），被取消轮前已有的完整 assistant 轮仍满足，追问链不断；首轮被取消则正确回退为新总结。
5. **「新对话时在跑任务的尾随 chunk 会污染新会话」——基本排除。** SW new-session 先 cancelCurrent（sw.ts:217）；host 单 NM port FIFO 保证 task-error(cancelled) 先于任何新任务帧到达，panel 侧终局解绑 + finished 拒收兜住。理论残留：cancel 前已在途的最后一个 chunk 若恰好落在新会话 pending 窗口会闪现一个随即被终局标错的气泡，窗口极窄且自愈。
6. **「IME Enter 误发送」——排除。** isComposing + keyCode 229 双守卫（SummarizeView.tsx:534-536）。
7. **「SW 30s 回收丢追问会话」——排除。** lastSession 持久化 storage.session + 冷启动恢复 + followUp 分支的同步补恢复（sw.ts:42-57, 193-194）。
8. **「历史大文件截断无提示」——排除。** host 截断时拼接「[... 已截断，全文见本地文件 path]」提示（stdio.ts:90-98）。

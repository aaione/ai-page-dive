## ③ confirmed 问题清单（双镜头验证过，按影响排序）

以下 7 条均为双镜头对抗验证中证据与方案双成立（或事实成立）的论断。标注【事实】= 有代码/文档证据；【观点】= 审查判断。

### P1.（medium）「零配置」支柱名实不完全相符——真实含义是「零账号/零 API key」而非「装完即用」

- 【事实】README.md 首屏大字「零配置」与「快速开始」的 curl|sh 终端安装命令 + 前置「已装并登录 Claude Code 或 Codex」并列存在；DECISIONS.md 自认「行业铁律：无产品做到扩展装完即用连本机程序，纯 CLI 产品只能显式一次终端命令」；README「为什么是 PageDive」已把「开箱即用」定义为「无账号、无 API key」——仓库内存在两套口径。
- 【事实】实际安装链是 macOS + Chrome + 已装已登录 CLI + 愿跑一次终端命令的四重筛选。
- 对抗验证：证据与方案双成立（证据三组逐条核实属实；方案零成本一行文案）。
- **行动**：首屏 headline 从「零配置」改为「零账号 · 零 API key · 复用已有订阅」，与正文/FAQ 口径拉平。避免 CWS 商店页被用户以「还要开终端」反噬。

### P2.（medium）CLI 版本漂移感知被动：probe 采到的 version 全仓零消费

- 【事实】packages/host/src/agents/registry.ts:100-107 probeAgents 跑 --version 拿到 version，但全仓消费点仅 4 处纯 UI 展示（Settings.tsx:554、SummarizeView.tsx:485/968、install.ts:136、index.ts:22）；grep min-version/semver/黑名单全仓零命中，无最低版本门控/已知坏版本提示；.github/workflows/ci.yml 矩阵只有 node:[18,22]；无 fixture 定期重采集机制。
- 【事实】解析器测试钉的 fixture 版本：claude 2.1.162（2026-09-01 采集）、codex 0.151.0、opencode 1.18.23——上游 CLI 自动升级后格式漂移只能等用户报障→人工重采样。
- 对抗验证：证据与方案双成立；核实确认解析器确无 unknown/default 分支。
- **行动**（三件套，合计约 50-80 行，host 现行 2132/2200 行红线内可容纳或放 extension 侧/scripts）：① probe 结果加 min-version / 已知坏版本比对，做成 UI 警告条而非硬拒跑（硬拒跑与零配置支柱冲突）；② scripts/record-fixtures.mjs 一键对真机 CLI 重采样刷新 test fixture（scripts/ 不计 host 行数）；③ 解析器维护 unrecognized 事件计数透传 debug 事件（约 10-15 行，注意为 claude 维护「已知但忽略的 type」白名单防误报）。

### P3.（medium）curl|sh 信任链「做了但没说」——钉版本防扩散的设计只写在脚本注释里，README 零呈现

- 【事实】README 快速开始②给出 `curl -fsSL .../install.sh | sh -s -- <扩展ID>`，通篇无「先读脚本源码」链接、无钉版本说明；而 install.sh:38-43 的 r33-sec 注释明确写了钉版本防扩散论证且实钉 `@0.1.3`。供应链安全设计存在于脚本内部、用户执行前不可见。
- 【事实】附带不一致：README 手动备选（折叠区）的 npm 命令反而未钉版本（`npm i -g @aaione/ai-page-dive`），与 install.sh 钉版策略矛盾。
- 对抗验证：证据与方案双成立；确认无「有意不呈现」的决策记录。
- **行动**：README curl 命令下补一行审阅指引（「钉版本安装、不下载二进制、纯 npm，源码可先读」）；FAQ 加「这条 curl|sh 安全吗」条目复用 r33-sec 论证；手动 npm 备选同步钉版本。

### P4.（medium）PRIVACY.md 仅中文正文——CWS 审核员可读性缺口

- 【事实】PRIVACY.md 标题双语「Privacy Policy / 隐私政策」但正文全中文；manifest.json description 已是中英双语；全仓库无任何英文隐私文本。r47 审计自己确认「CWS 审核与用户信任都会拿 PRIVACY.md 对账 manifest」。
- 对抗验证：证据与方案双成立（「国际用户」一半理由被削弱——UI 全中文，英文用户本就用不了；站得住的是 CWS 审核/英文申诉沟通一半，英文摘要节性价比最高）。
- **行动**：PRIVACY.md 补英文摘要节（而非全文），与双语标题、双语 description 对齐。

### P5.（medium）「零遥测」承诺与「看使用数据再决策」的措辞矛盾（降级为措辞修复）

- 【事实】DECISIONS.md 多引擎定案写「审校上线后看使用数据」，而 PRIVACY.md 承诺零遥测且全仓库确无任何统计管道——「使用数据」确无来源。
- 对抗验证：**证据推断被降级**（同句已自证决策信号实为「用户诉求」等定性信号，非量化遥测，故不构成 medium 级正确性矛盾），**但方案 B 成立且明显更优**：改为 GitHub issue/社区访谈等定性信号措辞，一句话零成本消解；opt-in 匿名计数方案 A 被驳回（需收集端点，直接破「无服务器」核心承诺，且 1-5% 采纳率的使用计数回答不了功能满意度问题）。
- **行动**：DECISIONS.md 该句措辞改为「看用户反馈/issue 等定性信号」，与零遥测承诺对齐。

### P6.（medium）首装重启口径：面板「通常会自动进入」与 install.sh「请完全退出 Chrome（⌘Q）后重开」措辞矛盾（降级为文案打磨）

- 【事实】install.sh RC=0 分支明示需 ⌘Q 重启；Onboarding.tsx 非卡装态文案称「通常会自动进入；若超过 1 分半未进入，多半需完全重启」。对抗验证证实 ⌘Q 指引第 0 秒就存在于常驻 note（并非「白等 90s 才拿到」），原论断的「被 90s 门控」前提被代码证伪；但首装场景 NM manifest 未被运行中 Chrome 加载、「通常自动进入」与终端口径的张力仍在（幂等重装场景则确实成立）。
- 【事实】附带发现真瑕疵：forbidden 分支共享 note 说「终端看到 🎉」，但 host install 输出刻意无 🎉（install.ts:142 注释）。
- **行动**：首装分支把 ⌘Q 提示提为安装命令下方主文案；forbidden 分支删「通常立即生效」侥幸表述；对齐「终端看到 🎉」与 install 实际输出。

### P7.（high，外部风险确认）最大平台风险在 Anthropic 条款而非 CWS，属外部不可控面

- 【事实】架构报告风险表自排序 #1 Anthropic 执法（高）vs #5 CWS review（中）；缓解全部是自我约束姿态（只子进程调起未修改官方二进制/零凭证/不代理流量），从未获得产品级官方背书；README FAQ 披露口径诚实。
- 【事实】护城河诚实定位（双镜头确认事实成立）：steipete/summarize（6.6k star、MIT、已上架 CWS）已占住「插件→本机 CLI 总结」约 85% 卖点；「可插拔 workflow 是核心壁垒：全部竞品均无此设计」；壁垒是执行壁垒而非结构壁垒。
- 对抗验证：证据成立；「更优方案」（做平备胎一键切换）增量被大幅高估——codex 切换已是一次下拉选择，opencode 被上游 Gatekeeper 问题锁死无可做，剩余增量仅预制迁移引导文案，属边际改进。
- 【观点】此项无可执行的产品内修复，正确姿势是维持合规红线 + 保持双适配器在册（已是现状）+ 对外叙事补差异化（见 A6/A7）。
- 注：2026-01 Anthropic 封禁第三方 harness 的外部事实因搜索限流无法在线复核，标注「仓库内自洽、外部未核实」；竞品当期状态部分为训练数据推断。

## ⑦ 方法论与局限

- **审查规模**：8 个维度各由独立审查 agent 产出论断（合计 30 条：9 sound / 10 problem / 8 risky / 2 optimal / 1 汇总性），随后每条 problem/risky/optimal 论断经双镜头对抗验证（第一镜头核证据是否属实、有无「有意设计」豁免；第二镜头独立核更优方案是否真更优），双过才进 confirmed 清单。12 组对抗验证中 7 组双成立、3 组证据被推翻/降级但方案或事实保留、其中 3 组的更优方案被驳回。
- **证据标准**：所有论断要求文件路径级证据；本报告区分【事实】（有代码/文档证据）与【观点】（审查判断）。
- **验证方式**：只读代码与文档，未启动浏览器/dev server，未修改任何文件（本报告除外）。
- **竞品数据时效**：2026 年现状在线查证因 WebSearch 配额限流（至 2026-10-02）失败。steipete/summarize 的存在与定位有 2026-08-31 调研快照的 GitHub API 实测记载（仓库内自洽）；其当期 star 数/在架状态、Anthropic 2026-01 封禁第三方 harness 的外部事实、macOS 在 CLI 订阅者中的占比，均标注为**训练数据推断或仓库内自洽、外部未核实**，不允许作为高置信决策依据。
- **已知盲区**：①「默认档 deep 与快扫错配」因零遥测无法用数据验证，属不可证伪的产品押注；②CWS 审核实际周期与通过率无先验数据；③本报告基于 r49 commit 后的工作区状态（含 6 个未提交修改文件）。
